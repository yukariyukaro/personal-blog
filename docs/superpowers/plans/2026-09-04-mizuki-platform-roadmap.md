# 成熟博客平台演进路线图

## 目标

在保留现有首页视觉、React 组件资产和 Git-backed 内容模式的前提下，将
`personal-blog` 建设为完整的静态内容平台。所有阶段遵守以下硬约束：

- 单个代码文件不超过 500 行。
- 采用 Model、ViewModel、View、Service 分层。
- 内容字段缺失时不生成默认业务文案；必填字段在构建期失败，可选字段缺失时隐藏对应 UI。
- 桌面、平板和移动端均有明确布局，不依赖整体缩放。
- 视觉沿用现有初音绿品牌，并参考 Mizuki 的密度、层级和阅读体验，不复制其主题。
- 每个阶段完成后运行 lint、类型检查、构建、单元测试和关键 E2E。

## 总体架构

```text
blog-content/
├── posts/                 # Markdown/MDX 文章
├── spec/                  # 关于、友链说明等长文本页面
├── data/                  # 项目、技能、时间线、日记、相册、番剧等结构化数据
└── images/                # 内容图片

apps/web/
├── scripts/
│   ├── content/           # 内容发现、校验、渲染、索引和静态页面生成
│   └── quality/           # 文件行数、链接、Feed、资源和构建产物检查
├── src/
│   ├── app/               # 路由、应用配置、Provider
│   ├── domain/            # 内容与特色页面领域模型
│   ├── services/          # 内容、评论、统计、外部 API 适配器
│   ├── features/          # 文章、搜索、评论、设置、音乐等功能模块
│   ├── pages/             # 页面组合层
│   └── shared/            # UI、样式 token、图标和通用工具
└── public/content/        # 构建生成，不提交
```

数据流统一为：

```text
Markdown / JSON
  -> 构建期 Schema 校验
  -> 规范化领域模型
  -> HTML / JSON / Feed / SEO 产物
  -> Service 读取
  -> ViewModel 派生交互状态
  -> View 渲染
```

## 阶段 0：架构基线与质量门禁

交付内容：

- 完成现有 BlogReader 重构闭环。
- 拆分超过 500 行的 CSS 和接近上限的组件。
- 增加自动文件行数检查。
- 修复或更新当前失真的 E2E 契约。
- 固化主题、搜索、目录、相关文章、URL 恢复和 Live2D 基线。

验收标准：

- 所有代码文件不超过 500 行。
- `pnpm lint`、`pnpm build`、单元测试和桌面/移动端 E2E 通过。
- 当前首页和文章阅读流程没有功能回退。

## 阶段 1：内容模型与渲染管线

交付内容：

- 扩展 Frontmatter：更新时间、草稿、置顶、优先级、语言、评论开关、作者、
  来源、许可证、别名和固定链接。
- 支持目录式文章和本地资源。
- 支持 Markdown 与受控 MDX。
- 支持提示块、代码高亮/复制/折叠/代码组、KaTeX、Mermaid、PlantUML、
  Wiki Link、GitHub 卡片、Spoiler、图片网格和灯箱。
- 页面正文、搜索索引和 Feed 复用同一规范化内容管线。

验收标准：

- 开发环境显示草稿，生产环境排除草稿。
- 每种扩展语法都有内容夹具和构建测试。
- 不可信 HTML 经过白名单清洗。
- 相对资源、站内链接和远程资源均能正确解析。

## 阶段 2：路由、SEO 与内容分发

交付内容：

- 独立文章 URL、alias 和 permalink。
- 文章级 title、description、canonical、Open Graph、Twitter Card 和 JSON-LD。
- RSS、Atom、Sitemap、robots.txt 和 IndexNow 产物。
- 归档、分类、标签和日历索引页面。
- 静态文章入口与客户端交互共用同一文章模型。

验收标准：

- 直接访问文章 URL 可得到完整 HTML，不依赖先进入首页。
- 禁止发布的草稿和加密正文不进入 Feed 或搜索索引。
- Feed XML、Sitemap 和结构化数据通过解析测试。

## 阶段 3：文章互动与统计

交付内容：

- 上一篇、下一篇、相关文章和随机文章。
- 最后修改时间、许可证、来源说明和分享海报。
- Giscus 与 Twikoo 可插拔评论适配器。
- 访问量与访客量 Provider 接口；未配置时隐藏，不展示伪造数字。
- 浏览器端文章加密和公开摘要隔离。

验收标准：

- 评论和统计凭据只通过环境变量提供。
- 加密文章正文不出现在列表、搜索、Feed 和静态 HTML 明文中。
- Provider 缺失时页面布局保持完整且不显示默认业务文本。

## 阶段 4：个人内容空间页面

交付页面：

- 关于
- 归档
- 友链
- 项目
- 技能
- 时间线
- 日记
- 相册与相册详情
- 番剧
- 设备
- AI 工具

每个页面使用独立领域模型、Repository、ViewModel 和 View。结构化内容来自
`blog-content/data`，长文本来自 `blog-content/spec`。

验收标准：

- 每个页面具备搜索或筛选、空状态、错误状态和响应式布局。
- 没有内容数据时不注入演示文案。
- 导航仅展示启用且有数据的页面。

## 阶段 5：设置、媒体与外部数据

交付内容：

- 统一设置面板。
- 深浅主题、主题色、壁纸模式、文章列表布局和动效偏好。
- 桌面与移动端不同壁纸资源。
- 音乐播放器与本地/Meting 数据源。
- Bangumi、Bilibili、Memos 的构建期同步适配器。
- 评论、统计和分析服务配置。

验收标准：

- 用户偏好可持久化并尊重 `prefers-reduced-motion`。
- 外部服务失败不阻断站点构建；对应功能进入明确不可用状态。
- 访问凭据不进入前端产物。

## 阶段 6：设计系统与响应式收口

视觉方向：

- “深海数字档案馆”：深色半透明表面、青绿色高亮、少量冷白和珊瑚警示色。
- 首页保持沉浸式视频与角色氛围；内容页强调扫描效率和长文阅读。
- 卡片圆角不超过 8px，只有浮层、播放器和特殊媒体容器可适度放宽。
- 不使用装饰性渐变球、嵌套卡片或大面积单一蓝紫色。

响应式矩阵：

| 视口 | 布局 |
| --- | --- |
| `>= 1440px` | 三栏内容布局，固定阅读目录，正文最大宽度受控 |
| `1024-1439px` | 双栏布局，右侧信息折叠为抽屉 |
| `768-1023px` | 单主栏，作者信息横向压缩，目录悬浮 |
| `< 768px` | 单栏，底部操作区，移动端筛选抽屉和目录面板 |

## 阶段 7：工程质量与发布收口

交付内容：

- 内容管线单元测试。
- 桌面、平板、移动端 Playwright 测试。
- 视觉截图与无重叠检查。
- 关键页面可访问性检查。
- 构建产物链接、字体、图片、Feed 和静态路由检查。
- Bundle 分析、首屏媒体延迟加载和字体子集化。
- GitHub Actions 发布门禁。

最终验收：

- 所有代码文件不超过 500 行。
- 所有必需检查通过。
- 页面在 390、768、1024、1440、1920 宽度下没有文本溢出或交互遮挡。
- 未配置外部服务时无虚假数据和默认业务文案。
- GitHub Pages 产物可直接访问全部公开路由。
