# 前端视觉与文字可读性规范

> 适用范围：`apps/web` 的页面、组件与 UI 样式。修改 UI 前必读。
> 响应式断点和三档布局的唯一规范仍是 `apps/web/.trae/rules/responsive-design.md`。

## 1. 风格不能以牺牲阅读为代价

本站是个人博客，不是游戏宣传图。可借鉴游戏官网的几何构图、切角、档案编号、非对称排版和视觉层次，但名称、项目简介、目录、操作提示和正文必须在正常浏览器缩放下直接读清。

- 视觉基准是当前首页首屏：墨绿黑底、黄绿标记、灰白文字、青色交互提示。
- 保留页面特色与既有交互；不能用统一卡片模板替代各页构图。
- 不引入字体来代替字号和层级修复。展示标题复用 Oswald / SmileySans，中文长段正文使用清晰的正文无衬线字体，档案标签可用等宽字体。
- 元数据与操作文案不是装饰，不能以“档案感”“高密度”或“参考截图如此”为理由缩成微字。

## 2. 字号底线（强制）

以下是**最终渲染大小**，以根字号 16px、浏览器缩放 100% 为验收基准。代码仍必须用 `rem` / `clamp()`，不能写 px 字号，也不能缩小 `html` 根字号绕过底线。

| 文字类型 | 最小值 | 推荐实现 |
|---|---|---|
| 正文、项目简介、主要操作与目录名称、输入文字 | 16px | `1rem` 起；桌面长正文可 `1.0625rem`，行高 1.7–1.9 |
| 分类、标签、辅助操作、当前状态等帮助理解内容的信息 | 推荐 14px，不低于 12px | 通常 `0.875rem`；紧凑布局最低 `0.75rem`，行高至少 1.4 |
| 低优先级辅助信息：英文档案代码、重复的编号说明、装饰性页脚 | 约 10px | 最低 `0.625rem`，必须保持足够对比；不得承载唯一的操作指引或主要内容 |
| 展示标题 | 按语义分层，不能拿正文缩小来制造层级 | 相对字号 / `clamp()`，三档检查换行 |

优先使用 `src/index.css` 的 `--font-body`、`--font-label`、`--font-control`、`--font-micro`。如空间不足，调整容器、留白、换行或折叠次要装饰，**不能降低主要内容字号**。10px 是低优先级辅助信息的允许下限，不是所有标签的默认字号。

### 缩放卡片也受底线约束

- `transform: scale()`、3D 旋转、父级缩放都会让文字实际变小；只检查 `getComputedStyle().fontSize` 不够。
- 例如卡片缩放为 0.8 时，重要辅助文字需至少 `1.125rem`（18 × 0.8 = 14.4px），简介需至少 `1.25rem`（20 × 0.8 = 16px）；低优先级代码至少 `0.8125rem`（13 × 0.8 = 10.4px）。还要计入封面旋转，不要刚好卡着下限。
- 中央卡、邻卡和 hover 状态都要检查。可以让侧卡更小，但不能把名称/简介压暗到不可读。
- 大幅旋转只施加给不含信息的外壳或装饰；包含文字的封面只允许轻微旋转，并仍需满足有效字号底线。
- 纯装饰水印可以透明/裁切，但不能承载任何唯一信息；不要给重要小字贴 `aria-hidden` 以规避测试。

## 3. 对比、字体与空间

- 普通文字对背景的对比度至少 4.5:1；大字号（24px 常规或约 18.7px 粗体）至少 3:1。
- 辅助文字使用可读的次级颜色，而不是低 opacity。禁止给包含名称、简介或按钮的整体容器叠加 `opacity` / `brightness` 来制造远近层次。
- 图片/视频上有文字时，给文字区独立衬底；不能依赖某一张图片碰巧够暗。
- 小字的长段中文避免展示斜体、过窄字体或过大字距。分类/代码标签允许自然换行。
- 不用固定高度截断正文，不让标题/说明被 `clip-path`、卡片边界、页码栏或导航遮挡。
- 全站增加字体时不得直接整体 zoom：这样会同时放大装饰、破坏交互位置，也不能修复文字层级。

## 4. 交付检查（强制）

1. 在 Playwright 的 `390 / 834 / 1440` 三档、浏览器缩放 100% 下，覆盖中央卡、左右邻卡、目录、详情正文、元数据与操作提示。
2. 用断言检查计算字号与父级累计缩放。可读性测试位于 `apps/web/tests/e2e/blog-readability.spec.ts`；缩放补偿要验证最终字号。
3. 将不截字、不叠字、无横向页面滚动及焦点写成 E2E 契约，文字对比通过前景/背景色验证。自动化未覆盖项必须明确报告；不默认逐页截图做人工视觉验收，截图不能替代断言。
4. 增加字号导致内容更高时，允许自然滚动；先减少装饰占位，不为了塞进一屏而缩字。
5. 必跑 `pnpm run check:responsive`、`pnpm exec playwright test blog-responsive.spec.ts`；改动文字布局时补跑 `pnpm exec playwright test blog-readability.spec.ts`。测试筛选与复验规则见 [verification-workflow.md](verification-workflow.md)。

**经验红线：主要内容使用 7–11px 微字、辅助文字缩放后低于 10px、缩小且整体压暗的侧卡、只有“元素可见”却未检查文字大小的测试，都不算可读性合格。**
