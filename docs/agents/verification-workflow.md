# AI 协作与 Web 验证

> 适用于 `apps/web`。跑测试、使用浏览器或派发子代理前按需读取。
> **覆盖义务、有效测试标准、产物与 AI 阅读契约见 [e2e-testing.md](e2e-testing.md)（正文）**；本文只管命令筛选、并发、成本与协作纪律。
> 本次耗时暴露的主要问题是开放式子代理收尾、重复验证、测试筛选失效和大量截图读取；不能简单归因于 E2E 太慢。

## 1. 上下文只保留可复用结论

- `AGENTS.md` 只放短规则和「何时读取」索引；具体经验放 `docs/agents/`，不要把任务日志、截图或完整工具说明常驻上下文。
- 修改已有规范时同步冲突表述；同一规则指定一个正文来源，其它入口只链接，不复制整套流程。
- 新知识必须能改变后续行动；一次性时长、用例总数、端口、工具故障不要写成永久事实。

## 2. 子代理要有明确结束条件

- 派发前写明文件写入范围、组件接口和验收条件；要求「完成即报告，不追加探索或自检轮次」。小任务直接做，不为并行而拆分。
- 只有写入范围独立、接口已稳定的任务才并行。测试编写可以与实现并行，但统一验收必须等相关改动结束。
- 默认子代理只做必要的局部检查，**不各自启动 E2E、服务或浏览器验收**；由主会话汇总结果、统一运行并报告。
- 不同时运行多套浏览器测试。代理报告的检查结果可以复用，不机械重跑；最终验证必须覆盖合并后的代码。

## 3. 明确筛选测试，按变更复验

以下命令在 `apps/web` 执行：

```bash
pnpm run check:responsive
pnpm exec playwright test blog-responsive.spec.ts
# 改字号/文字布局时加可读性契约；专项行为只选对应 spec
pnpm exec playwright test blog-readability.spec.ts portfolio-motion.spec.ts
pnpm run check
```

- 本次 `pnpm run test:e2e -- blog-responsive` 实际误跑了全量套件。**统一使用 `pnpm exec playwright test <完整 spec 文件名>`**，启动后核对列出的文件和用例范围；发现范围不符即停止纠正，不等全量跑完。
- 优先沿用 `playwright.config.ts` 的服务与 `workers: 1`。复用已有服务时，`E2E_BASE_URL` 必须取实际启动地址，不猜端口、不重复起服务。
- 验证集中在实现收敛后。修复失败项先复跑相关 spec；最后一轮覆盖变更，不因新增文档或截图证据再跑完整门禁。
- 后续又改 CSS 时仍需复验受影响的布局/可读性 E2E，不能只凭静态守卫断言页面通过。纯文档改动检查链接、命令一致性和 diff 即可。
- 浏览器资源或网络错误先核对并发任务与失败现场，不把一次基础设施故障当成产品缺陷，也不无依据重启或修改测试配置。

## 4. Playwright 为主，不默认做人工视觉验收

- Web 验证主要依靠 Playwright E2E：三档布局、字号、图片比例、遮挡、溢出、交互、焦点与减弱动效写成可回归的断言；静态、类型及单测继续承担各自职责。
- **验收先读产物，不读页面**：每次运行自动产出 `output/e2e-report/summary.md`（结论、失败项、动作时间线、跳过原因、截图索引）。AI 默认只读它；需要视觉证据时按索引读单张关键节点截图；报告不足再展开 trace 文本。读取顺序与产物契约见 [e2e-testing.md](e2e-testing.md) 第 7 节。
- **不默认启动交互浏览器逐页看图、不批量读取整页 PNG、不把人工视觉验收作为交付门禁。** 浏览器仅用于自动化无法解释的失败排查；优先日志、trace 和定点信息。
- 仅在用户要求截图或故障定位确有需要时，用 Playwright 生成有限证据；截图本身不等于测试通过。内嵌浏览器本次出现过超时和拼接异常，不应持续重试同一路径。
- 若需要稳定的像素回归，再建立受控浏览器/字体/动画环境与基线审批；几何断言不能证明美术质量，不提前宣称已有完整视觉测试框架。

## 5. 收尾只交付结果

- 工具说明读过即可复用；文件未变化不重复读取，截图超时不原样反复重试。
- 最终报告写清完成内容、实际测试范围和结果、未覆盖项；不粘贴测试日志，不为了交付主动生成一整套截图。
