# 前端 E2E 测试规范（apps/web）

> 本文是**前端测试的正文规范**：覆盖义务、有效测试标准、产物与 AI 阅读契约。
> 命令筛选、并发与子代理纪律见 [verification-workflow.md](verification-workflow.md)；断点与三档行为见 [responsive-design.md](../../apps/web/.trae/rules/responsive-design.md)。

## 1. 一句话原则

**用户能做的交互，必须有 E2E 契约；E2E 的验收结论高于单元测试。**

前端测试以 Playwright E2E 为主。单元测试只补充无法通过页面交互表达的逻辑，不能替代页面验收。

## 2. 覆盖义务

覆盖单位是**用户可执行的操作与流程**，不是函数或组件数量。

只要是用户能触发的交互，就要有对应用例：

- 点击、键盘激活、悬停、聚焦、触摸滑动、滚轮。
- 页面跳转、打开详情、返回、前后切换、直达链接与刷新。
- **连续流程**：前一步产生的状态如何影响下一步。
- **异常路径**：加载失败、请求失败、重复操作、转场期间操作、空数据。

「某一步已经测过」不等于「组合路径也测过」。作品页的实际教训：单看「点击打开详情」是通的，但「方向键切换后再按 Enter」打开的是旧作品。

优先级排序：核心流程 → 跨状态组合 → 异常路径 → 边缘视觉。

## 3. 什么才算有效测试

每个用例必须能回答四件事：**前置状态、用户操作、预期结果、禁止结果**。

断言必须落在用户可感知的结果上：内容、选中态、URL、焦点、滚动位置、可操作性、以及**不应该发生的副作用**。

以下是无效测试，不得作为验收依据：

- 只断言元素存在或可见。
- 调用了 `.click()` 没有报错就当作通过。
- URL 变了但没确认页面内容。
- 断言内部状态字段或组件 props，而非页面表现。
- 用 `evaluate()` 直接改状态、调用回调、绕过用户操作让页面进入目标状态。
- 因为实现改了就把断言改宽松、删用例、加 `skip` 或加长 `timeout`。

判断标准只有一句：**如果这个交互真的坏了，这个用例会不会失败？**

## 4. 真实输入，不绕过被测行为

优先用 Playwright 的真实操作：`click` / `tap` / `hover` / `keyboard.press` / `fill` / `goBack` / `goForward` / 原生触摸输入。

- 触摸、滚轮这类和浏览器行为强相关的交互，必须用真实输入事件，不用 DOM 派发模拟。
- 平台快捷键无法由自动化可靠触发时（例如 `Alt+Left` 后退），改为断言真实事件是否被页面消费，另用 `goBack()` 验证历史行为，不要伪造结论。
- 允许在边界受控：中止图片请求、模拟接口失败、断网。不允许 mock 掉正在验收的组件或交互逻辑。

## 5. 设备与状态矩阵

Playwright 配置了三个视口项目：`desktop-chromium`（1440×900）、`tablet-chromium`（834×1112）、`mobile-chromium`（390×844）。

- 布局、触摸、遮挡、焦点相关的交互要验证**适用档位**。
- 键鼠交互不能只在某一档验证；触摸交互在平板与手机都要跑。
- 动效影响操作时，正常动效与减弱动效（`prefers-reduced-motion: reduce`）都要覆盖。配置默认 `reduce`，需要动效的用例显式 `page.emulateMedia({ reducedMotion: 'no-preference' })`。
- 几何断言要检查**真实容器边界**：裁切盒、遮挡、越界。只断言「页面没有横向滚动」不够——作品页的磁带越界就是容器内部裁切，页面并不横滚。
- 可以按设备能力跳过不适用用例（粗指针不跑 hover）；**不允许因为某档功能坏了而跳过**。

## 6. 单元测试的职责边界

单元测试只做这些：

- 纯函数与数据变换的边界。
- 类型契约、数据合法性。
- 构建脚本、路由扫描、静态守卫。
- 用户无法直接触发的确定性逻辑。

以下必须由 E2E 证明，不能只写单测：点击后的内容、URL 与页面同步、焦点恢复、手势误触、异步失败后的可用性、多组件协作。

**代价要认。** E2E 比单测慢、比单测贵，用例数量增长会带来维护成本。因此：

- 迭代时只跑受影响的 spec，全量套件在收口时跑一次。
- 出现 flaky 先修根因，不靠重试掩盖。
- 单测通过不等于功能正确：**E2E 失败时，以 E2E 为准。**

## 7. 产物与 AI 阅读契约

**AI 验收只读测试产物，不自己打开页面、不通读整页截图。**

每次运行结束自动产出 Markdown 验收报告：

```bash
cd apps/web
pnpm exec playwright test <spec 文件名>   # 结束时自动写报告
```

| 产物 | 路径 | 用途 |
|---|---|---|
| 验收报告 | `output/e2e-report/summary.md` | **首选读物**：结论、失败项、错误、动作时间线、跳过原因、截图索引 |
| 关键节点截图 | `output/e2e-report/screenshots/<视口>/<名称>.png` | 定点视觉证据，按需读取 |
| trace | `output/playwright/test-results/**/trace.zip` | 报告不足以定位时再展开 |
| trace 文本 | `pnpm exec playwright trace open <zip>` 后 `trace actions` / `errors` / `console` | 机器可读的动作与错误时间线 |

读取顺序：

1. 先读 `summary.md`。失败的用例带错误摘要与**动作时间线**（含失败步、耗时与超时），多数问题到此即可定位。
2. 时间线不足时，按报告给出的命令展开 trace 文本。
3. 只有需要视觉判断时，才读报告索引里对应名称的单张截图。

截图是定点证据，不是通读材料：不要批量读取整页 PNG，也不要为了「看整体」把多张图读进上下文。

### 采集约定

- 关键节点截图由 `tests/e2e/acceptance-evidence.spec.ts` 在主要页面状态下采集，三档各一份，命名语义化（如 `作品-详情-原创封面`）。
- 行为 spec 需要额外证据时调用 `captureCheckpoint(page, test.info(), '<语义名称>')`（`tests/e2e/report-helpers.ts`）。默认只截当前视口，`{ fullPage: true }` 需有明确理由。
- 失败用例自动保留截图、trace 与视频；常规运行不开启屏幕录制快照，避免产物体积失控。

## 8. 改动前的自检清单

1. 这次改动影响哪些**用户操作**？对应 spec 是否覆盖？没有就先补用例，并确认它在旧实现上会失败。
2. 是否覆盖连续流程与异常路径，而不只是单点操作？
3. 断言是否落在用户可观察结果上，且包含「不应发生什么」？
4. 三档视口与减弱动效是否都验证了适用部分？
5. 跑完读 `output/e2e-report/summary.md`，确认结论与失败原因，再决定是否需要 trace 或截图。
