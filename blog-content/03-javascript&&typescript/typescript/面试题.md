## 一、类型系统基础

### 1. TypeScript 中 interface 与 type 的区别？

参考：https://zhuanlan.zhihu.com/p/558315566 ｜ 官方文档：https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#differences-between-type-aliases-and-interfaces

- **表达能力**：`interface` 只能描述对象 / 函数 / 类的结构；`type` 无限制，可为联合类型、交叉类型、元组、基本类型别名、条件类型等。
- **扩展方式**：`interface` 用 `extends` 继承，且支持**声明合并**（同名 interface 自动合并）；`type` 用交叉类型 `&` 组合，且**不能重复声明**。
- **计算能力**：`type` 支持映射类型、条件类型等类型运算，`interface` 不支持。
- **选型建议**：定义对象 / 类的公共契约（尤其是需被继承或合并的 API）优先 `interface`；需要联合、交叉、类型运算时用 `type`。

### 2. any、unknown、never、void 的区别？

参考：https://www.typescriptlang.org/docs/handbook/2/functions.html#unknown ｜ https://www.typescriptlang.org/docs/handbook/2/narrowing.html#the-never-type

- **`any`**：关闭类型检查，可赋值给任何类型也可被任何类型赋值，会「传染」，应尽量避免。
- **`unknown`**：类型安全版的 `any`。任何值都可赋给它，但使用前必须先**类型收窄**，否则报错。
- **`never`**：永不存在的值的类型（抛异常、死循环、穷尽性检查的兜底分支）。是所有类型的子类型，可赋给任何类型，但没有任何类型可赋给它（除 never 本身）。
- **`void`**：表示没有返回值，通常用于函数返回类型；变量类型为 `void` 时只能赋 `undefined`。

### 3. TypeScript 有哪些基本类型？

参考：https://www.typescriptlang.org/docs/handbook/2/everyday-types.html

- 原始类型：`string` / `number` / `boolean` / `bigint` / `symbol` / `null` / `undefined`。
- 特殊类型：`any` / `unknown` / `never` / `void` / `object`。
- 复合类型：数组 `T[]`、元组 `[T, U]`、枚举 `enum`、联合 `A | B`、交叉 `A & B`、字面量类型（如 `'a' | 'b'`、`1 | 2`）。

### 4. 枚举（enum）有什么特点？const enum 有何不同？

参考：https://www.typescriptlang.org/docs/handbook/enums.html

- 数字枚举默认从 0 递增，且有**反向映射**（值→名）；字符串枚举无反向映射。
- 数字枚举编译后会生成一个双向映射的对象，有运行时开销。
- `const enum` 在编译期被**内联**为字面量，不生成对象，体积更小、性能更好，但不支持反向映射，且在某些打包 / `isolatedModules` 场景下有兼容问题。

### 5. TypeScript 的类型是结构化（Structural Typing）还是名义化（Nominal）的？

参考：https://www.typescriptlang.org/docs/handbook/type-compatibility.html

- TypeScript 采用**结构化类型**（鸭子类型）：只要结构（成员）兼容即认为类型兼容，不看名字。
- 想模拟名义类型可用「品牌 / 打标」技巧：`type UserId = string & { readonly __brand: unique symbol }`。

## 二、进阶类型与类型运算

### 6. 泛型（Generics）是什么？有什么用？

参考：https://www.typescriptlang.org/docs/handbook/2/generics.html

- 泛型让类型成为「参数」，在保持类型安全的同时复用逻辑，避免用 `any` 丢失类型信息。
- 常见能力：泛型约束 `T extends U`、默认泛型 `<T = string>`、在函数 / 接口 / 类 / 类型别名中使用。

### 7. keyof、typeof、in、索引访问类型 T[K] 分别是什么？

参考：https://www.typescriptlang.org/docs/handbook/2/keyof-types.html ｜ https://www.typescriptlang.org/docs/handbook/2/indexed-access-types.html

- **`keyof T`**：取对象类型所有键组成的联合类型。
- **`typeof x`**：在类型上下文中获取变量 / 对象的类型。
- **`in`**：用于映射类型中遍历联合类型的每个成员。
- **`T[K]`**：索引访问类型，取某个属性的类型。

### 8. 内置工具类型（Utility Types）有哪些？如何实现？

参考：https://www.typescriptlang.org/docs/handbook/utility-types.html

- 常用：`Partial<T>`、`Required<T>`、`Readonly<T>`、`Pick<T, K>`、`Omit<T, K>`、`Record<K, T>`、`Exclude<T, U>`、`Extract<T, U>`、`NonNullable<T>`、`ReturnType<T>`、`Parameters<T>`、`Awaited<T>`。
- 手写示例：

```ts
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyPick<T, K extends keyof T> = { [P in K]: T[P] };
type MyExclude<T, U> = T extends U ? never : T;
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
```

### 9. 条件类型与 infer 关键字？

参考：https://www.typescriptlang.org/docs/handbook/2/conditional-types.html

- 条件类型：`T extends U ? X : Y`，用于根据类型关系做分支判断。
- `infer`：在条件类型中**声明并推断**一个待定类型变量，如从函数类型中提取返回值 `infer R`、从数组中提取元素类型 `infer E`。

### 10. 什么是分布式条件类型（Distributive Conditional Types）？

参考：https://www.typescriptlang.org/docs/handbook/2/conditional-types.html#distributive-conditional-types

- 当条件类型作用于「裸露的泛型参数」且该参数是联合类型时，会对联合的每个成员**逐个分发**再合并。
- 例：`type ToArray<T> = T extends any ? T[] : never; ToArray<string | number>` 得到 `string[] | number[]`。
- 想阻止分发可用 `[T] extends [U]` 把它包起来。

### 11. 映射类型（Mapped Types）与键重映射？

参考：https://www.typescriptlang.org/docs/handbook/2/mapped-types.html

- 通过 `[K in keyof T]` 遍历键生成新类型，可加 / 减修饰符 `+?` `-?` `+readonly` `-readonly`。
- 键重映射：`[K in keyof T as NewKey]`，可配合模板字面量类型改键名（如生成 getter）。

### 12. 模板字面量类型（Template Literal Types）？

参考：https://www.typescriptlang.org/docs/handbook/2/template-literal-types.html

- 允许在类型层面拼接字符串字面量，如 `` type Event = `on${Capitalize<'click' | 'hover'>}` ``。
- 配合 `Uppercase` / `Lowercase` / `Capitalize` / `Uncapitalize` 内置工具做字符串类型变换。

## 三、类型收窄与断言

### 13. 类型收窄（Type Narrowing）有哪些方式？

参考：https://www.typescriptlang.org/docs/handbook/2/narrowing.html

- `typeof` 守卫、`instanceof` 守卫、`in` 操作符、字面量相等判断、真值收窄（truthiness）。
- 自定义类型守卫：`function isFish(x: Pet): x is Fish { ... }`。
- 可辨识联合（Discriminated Unions）：通过公共字面量字段（如 `kind`）区分成员，配合 `switch` 做穷尽检查。

### 14. 类型断言（as）与 as const 的区别？

参考：https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#type-assertions ｜ https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-4.html#const-assertions

- `as T`：告诉编译器「相信我这是 T」，不做运行时转换，滥用会绕过类型安全。
- `as const`：常量断言，把字面量推断为最窄的只读字面量类型（对象属性变 `readonly`、数组变只读元组）。

### 15. 非空断言 `!` 是什么？有什么风险？

参考：https://www.typescriptlang.org/docs/handbook/release-notes/typescript-2-0.html#non-null-assertion-operator

- `x!` 告诉编译器 `x` 不为 `null | undefined`，跳过检查。
- 风险：仅在编译期生效，运行时若真为 null 仍会报错，属于「向编译器打包票」，应谨慎使用。

### 16. 可选链 `?.` 与空值合并 `??` 与 `||` 的区别？

参考：https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-7.html

- `?.`：访问链路中出现 `null/undefined` 时短路返回 `undefined`。
- `??`：仅当左侧为 `null/undefined` 时取右侧；`||` 对所有 falsy 值（`0`、`''`、`false`）都取右侧，语义不同。

## 四、面向对象与声明

### 17. TypeScript 中的访问修饰符（public/private/protected/readonly）？

参考：https://www.typescriptlang.org/docs/handbook/2/classes.html#member-visibility

- `public`（默认）：处处可访问。
- `private`：仅类内部可访问（TS 的 private 是编译期约束；JS 原生 `#field` 是运行时私有）。
- `protected`：类及子类可访问。
- `readonly`：只读，仅可在声明或构造函数中赋值。

### 18. 声明合并（Declaration Merging）是什么？

参考：https://www.typescriptlang.org/docs/handbook/declaration-merging.html

- 同名的 `interface` / `namespace` 会被自动合并；接口合并常用于扩展第三方库类型（如给 `Window` 增字段）。
- `type` 不支持声明合并。

### 19. `declare` 关键字与 `.d.ts` 声明文件的作用？

参考：https://www.typescriptlang.org/docs/handbook/declaration-files/introduction.html

- `declare` 声明「存在但在别处实现」的类型 / 变量 / 模块，用于描述 JS 库或全局变量，不产生实际代码。
- `.d.ts` 是只含类型信息的声明文件，为 JS 库提供类型支持（如 `@types/*`）。

### 20. 抽象类（abstract）与接口的区别？

参考：https://www.typescriptlang.org/docs/handbook/2/classes.html#abstract-classes-and-members

- 抽象类可包含实现（方法体、字段），不能被实例化，用于共享逻辑 + 强制子类实现抽象成员。
- 接口只描述结构、无实现，一个类可 `implements` 多个接口但只能 `extends` 一个类。

## 五、配置与工程化

### 21. tsconfig.json 中 strict 模式包含哪些检查？

参考：https://www.typescriptlang.org/tsconfig/#strict

- 开启 `strict: true` 等于同时打开：`strictNullChecks`、`strictFunctionTypes`、`strictBindCallApply`、`strictPropertyInitialization`、`noImplicitAny`、`noImplicitThis`、`useUnknownInCatchVariables`、`alwaysStrict` 等。
- 其中 `strictNullChecks` 最关键：`null` / `undefined` 不再默认属于所有类型，需显式处理。

### 22. 协变、逆变与 `strictFunctionTypes`？

参考：https://www.typescriptlang.org/docs/handbook/release-notes/typescript-2-6.html#strict-function-types

- 协变（covariant）：返回值位置，子类型可赋给父类型。
- 逆变（contravariant）：函数参数位置，在 `strictFunctionTypes` 下按逆变严格检查。
- 双向协变：方法（method）语法的参数默认双向协变（历史兼容），普通函数属性则严格。

### 23. TypeScript 编译过程 / 类型擦除？

参考：https://www.typescriptlang.org/docs/handbook/intro.html

- TS 先做类型检查，再**擦除类型**编译为 JS，类型信息在运行时不存在（`enum`、装饰器元数据等除外）。
- 因此不能在运行时用 `instanceof` 判断接口，需要靠类型守卫或运行时校验库（如 zod）。

### 24. `interface extends` 与交叉类型 `&` 处理冲突属性有何不同？

参考：https://www.typescriptlang.org/docs/handbook/2/objects.html#extending-types

- `interface extends` 遇到同名但不兼容的属性会**报错**。
- 交叉类型 `&` 遇到冲突属性会得到 `never`（两者不可能同时满足），不报错但结果不可用。

### 25. 什么是类型体操 / 如何练习复杂类型？

参考：https://github.com/type-challenges/type-challenges

- 「类型体操」指用条件类型、映射类型、`infer`、递归类型等组合实现复杂类型逻辑。
- 推荐通过 type-challenges 仓库由易到难练习（实现 `Pick`、`Awaited`、`DeepReadonly`、`Flatten` 等）。

## 六、常见易错点速记

- `strictNullChecks` 关闭时 `null/undefined` 会「隐身」，排查困难 —— 建议始终开启 `strict`。
- 不要用 `as` 强行抹平类型报错，优先用类型守卫真正收窄。
- `object`、`{}`、`Object` 三者含义不同：`{}` 几乎等于任意非 null/undefined 值，范围极宽，慎用。
- 泛型参数不加约束时是 `unknown`，需要属性访问时记得 `T extends ...` 约束。
- 枚举优先考虑 `const enum` 或联合字面量类型以减小运行时体积。
