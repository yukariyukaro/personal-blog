## 库 (Library) 与框架 (Framework)

库和框架都是“别人写好的代码”，都能帮助我们少造轮子、提升开发效率。它们最核心的区别不是体积大小，也不是功能多少，而是：**谁掌握程序的控制权**。

一句话概括：

> **库：你调用它。**
> **框架：它调用你。**

这个差异也叫 **控制反转**（IoC, Inversion of Control）。当你使用库时，主流程由你决定；当你使用框架时，框架已经规定了应用的大体结构和执行流程，你只是在合适的位置填入自己的代码。

## 一、什么是库

库更像一个工具箱。你需要某个能力时，就主动调用它；不用的时候，它不会影响你的程序结构。

例如：

- `lodash`：处理数组、对象、函数等常见数据操作。
- `axios`：发送 HTTP 请求。
- `day.js`：处理日期和时间。
- `jQuery`：简化 DOM 操作、事件处理和 Ajax 请求。

以 `lodash` 为例：

```js
import _ from 'lodash';

const data = [1, 2, 3, 4];
const result = _.chunk(data, 2);

console.log(result); // [[1, 2], [3, 4]]
```

这里是我们主动调用 `_.chunk()`，调用结束后，程序继续按我们写的流程执行。

再比如一个页面只需要做表单校验、简单动画或发一个请求，用 `jQuery`、`axios` 这类库就够了。它们只解决局部问题，不要求你重写整个应用结构。

## 二、什么是框架

框架更像一套已经搭好的应用骨架。它不只是提供某个函数，而是规定了应用应该怎么组织、数据怎么流动、页面什么时候渲染、代码什么时候执行。

例如：

- `Vue`：提供组件、响应式、模板、生命周期等完整前端开发方式。
- `Angular`：提供路由、依赖注入、表单、工程规范等完整方案。
- `Django`：提供路由、模板、ORM、后台管理等 Web 开发结构。
- `Spring`：提供 Java 后端应用的组织方式和运行机制。

以 React 组件为例：

```jsx
function App() {
  useEffect(() => {
    console.log('React 在合适的时机执行这段代码');
  }, []);

  return <h1>Hello React</h1>;
}

createRoot(document.getElementById('root')).render(<App />);
```

我们写了 `App` 组件，但组件什么时候渲染、什么时候更新、`useEffect` 什么时候执行，都是 React 决定的。也就是说，React 掌握了渲染流程。

严格来说，React 官方称自己是“库”，因为它主要关注 UI 层；但在实际使用中，React 会控制组件渲染和生命周期，所以它也有很强的框架特征。

## 三、核心区别

| 维度 | 库 (Library) | 框架 (Framework) |
| --- | --- | --- |
| 控制权 | 在开发者手里 | 在框架手里 |
| 调用关系 | 你调用库 | 框架调用你 |
| 解决范围 | 通常解决某个具体问题 | 通常提供一整套开发方式 |
| 使用方式 | 需要时引入和调用 | 应用围绕它的规则组织 |
| 约束强度 | 较弱，更灵活 | 较强，需要遵守约定 |
| 替换成本 | 通常较低 | 通常较高 |
| 常见例子 | lodash、axios、day.js、jQuery | Vue、Angular、Django、Spring |

## 四、怎么判断

可以问自己一个问题：**程序的主流程在谁手里？**

- 如果主流程是你写的，只是在某些地方调用别人的函数，那更像是库。
- 如果主流程已经由别人搭好，你的代码是在固定时机被调用，那更像是框架。

所以，库和框架不是完全对立的概念。很多工具会介于两者之间，也可能随着使用方式不同而表现不同。比如 Vue 可以只在页面局部增强交互，也可以配合路由、状态管理和构建工具组成完整应用；React 单独看偏库，配合路由、状态管理、工程框架后，也会越来越像完整框架。

## 五、如何选择

如果只是解决一个小问题，比如发请求、格式化日期、处理数组，用库更合适。它简单、灵活、替换成本低。

如果要开发一个复杂应用，比如后台管理系统、电商站点、单页应用，框架通常更合适。它能提供统一结构和开发约定，让团队更容易协作，也能减少从零搭建基础能力的成本。

简单总结：

> **库给你工具，框架给你规则。**
> **库提高局部效率，框架组织整体应用。**
