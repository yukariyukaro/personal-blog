# HTML 的诞生

## 核心结论

HTML 的诞生不是为了“做漂亮网页”，而是为了解决早期 Web 的核心问题：

> 如何用一种简单、开放、跨平台的格式，把分散在不同电脑上的文档连接起来，并让不同浏览器都能读懂。

从历史上看，HTML 是 Web 的“文档表达语言”。它和 URL、HTTP 一起构成了早期 Web 的基础：

| 问题 | 对应技术 |
|------|----------|
| 资源在哪里？ | URL |
| 资源怎么传输？ | HTTP |
| 资源内容怎么表达？ | HTML |

## 1. 为什么需要 HTML

Web 诞生前，互联网已经存在，但它更像一套“机器之间传输信息的基础设施”。人们可以发邮件、传文件、远程登录机器，但还缺少一种足够简单的方式，让普通用户在不同文档之间自由跳转。

Tim Berners-Lee 当时在 CERN 工作。CERN 有大量科学家、实验、设备、软件、论文和技术文档，信息散落在不同机器、不同系统、不同格式中。更麻烦的是，人员流动很频繁，很多信息虽然被记录了，但后来很难再找到。

Tim Berners-Lee 在 1989 年的提案中明确说，这个问题来自“复杂演化系统中的信息丢失”，解决方向是一个“分布式超文本系统”。简单说，他想解决的不是排版问题，而是：

> 如何让信息被记录、被连接、被查找、被继续扩展。

如果只把文档当作普通文件下载，用户仍然需要知道文件在哪里、用什么软件打开、相关资料在哪里。Web 的想法是：文档内部可以直接包含链接，用户看到相关内容时，点击就能跳到另一份文档。

所以 HTML 的必要性在于：Web 需要一种统一格式来描述这些可互相连接的文档。

| 需求 | HTML 提供的能力 |
|------|----------------|
| 表达一篇文档 | 标题、段落、列表、引用等结构 |
| 连接另一份文档 | `a` 元素和 `href` 属性 |
| 嵌入其他资源 | 图片、表单等内容 |
| 跨机器传输 | 普通文本格式，易于传输和解析 |
| 跨平台展示 | 浏览器负责按本机能力渲染 |

这也是为什么早期 HTML 文档并不复杂。它首先服务的是“全球信息共享”，不是现代意义上的复杂应用界面。

## 2. HTML 概念的简单解析

HTML 全称是 **HyperText Markup Language**，可以拆成三部分理解。

| 概念 | 中文 | 含义 |
|------|------|------|
| HyperText | 超文本 | 带有链接能力的文本 |
| Markup | 标记 | 给内容补充结构和语义说明 |
| Language | 语言 | 浏览器和作者共同遵守的一套规则 |

### 超文本是什么

普通文本是线性的。你从第一页读到第二页，再读到第三页。

超文本不是严格线性的。它允许文本中包含链接，你可以从当前内容跳到另一份相关内容。

```text
普通文本：A -> B -> C

超文本：A -> B
       A -> D
       B -> E
```

这正是 Web 名字里的 “Web” 含义：信息不再只是一本固定顺序的书，而是一张由链接连接起来的网。

例如：

```html
<a href="https://www.w3.org/">W3C</a>
```

这段 HTML 表示：页面上有一段文本 `W3C`，它指向另一个资源地址。浏览器看到 `a` 和 `href` 后，就知道这不是普通文字，而是一个可以跳转的链接。

### 标记是什么

标记不是修改内容本身，而是在内容旁边加说明。

例如，单看下面这段文字：

```text
HTML 的诞生
HTML 最初是为了解决信息共享问题。
```

浏览器不知道第一行是标题，第二行是段落。加上 HTML 标记后：

```html
<h1>HTML 的诞生</h1>
<p>HTML 最初是为了解决信息共享问题。</p>
```

浏览器就能知道：

| 内容 | 语义 |
|------|------|
| `HTML 的诞生` | 一级标题 |
| `HTML 最初是为了解决信息共享问题。` | 段落 |

所以，HTML 的本质不是“让文字变好看”，而是：

> 给内容添加机器可理解的结构和语义。

## 3. 为什么 HTML 选择以元素为基础

HTML 的元素语法并不是凭空发明的。早期 HTML 很大程度上继承了 SGML 的思想。SGML 是一种更早的通用标记语言标准，它关注的是：如何把文本标记成标题、段落、列表项等结构单元。

这和 Web 文档的需求天然匹配。

### 原因一：文档本来就是由结构块组成的

一篇文档不是一串没有边界的字符，而是由不同部分组成：

| 文档内容 | HTML 元素 |
|----------|-----------|
| 文档标题 | `h1` |
| 正文段落 | `p` |
| 条目列表 | `ul` / `li` |
| 引用内容 | `blockquote` |
| 跳转链接 | `a` |

用元素表示这些结构，刚好符合人类理解文档的方式，也方便浏览器解析。

### 原因二：元素可以表达“范围”

很多语义不是作用于一个字符，而是作用于一整段内容。

```html
<p>HTML 是 Web 的文档表达语言。</p>
```

这里 `<p>` 和 `</p>` 之间的所有内容都属于这个段落。元素用“开始标签 + 内容 + 结束标签”表达范围，比在每个字符旁边重复说明更自然。

### 原因三：元素可以嵌套，适合表达树形结构

文档通常有层级关系：页面里有文章，文章里有标题和段落，段落里可能有链接。

```html
<article>
  <h1>HTML 的诞生</h1>
  <p>HTML 让文档可以通过 <a href="https://www.w3.org/">链接</a> 互相连接。</p>
</article>
```

这段结构可以理解成一棵树：

```text
article
├── h1
└── p
    └── a
```

这对浏览器非常重要。浏览器解析 HTML 后，会得到类似树的结构，后续 CSS 设置样式、JavaScript 操作页面，都建立在这个结构之上。

### 原因四：元素负责语义，属性负责补充信息

元素说明“这是什么”，属性说明“它有什么附加信息”。

```html
<a href="https://example.com">查看详情</a>
<img src="./logo.png" alt="网站 Logo">
```

| 代码 | 元素语义 | 属性补充 |
|------|----------|----------|
| `a` | 这是链接 | `href` 说明链接地址 |
| `img` | 这是图片 | `src` 说明图片地址，`alt` 说明替代文本 |

这种设计很适合 Web：内容结构保持简单，额外信息通过属性扩展。

### 原因五：元素让结构和显示分离

HTML 最初强调的是文档结构，而不是固定排版。也就是说，HTML 负责说明：

> 这是什么内容。

至于它最终显示成什么样，由浏览器、设备能力、用户设置和后来的 CSS 决定。

这对 Web 很关键。因为 Web 面向不同机器、不同系统、不同屏幕，不能假设所有设备都有同样的字体、窗口大小和显示能力。

用元素描述结构，比直接描述“在屏幕第几像素画什么”更适合跨平台传播。

## 小结

HTML 的历史逻辑可以压缩成一句话：

> Web 需要连接文档；连接文档需要统一格式；统一格式需要描述文档结构；文档结构最自然的表达单位就是元素。

因此，学习 HTML 时，不应该把重点放在死记标签大全，而应该先理解：

| 学习重点 | 解释 |
|----------|------|
| HTML 解决什么问题 | 让 Web 文档可表达、可连接、可被浏览器理解 |
| 超文本是什么 | 带链接的文本，让信息组成网络 |
| 元素是什么 | 给一段内容标记结构和语义的基本单位 |
| 属性是什么 | 给元素补充必要信息 |

HTML 的核心不是语法复杂，而是抽象清晰：**用元素描述内容结构，用链接连接信息网络。**
