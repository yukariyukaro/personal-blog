## 计算机是什么

上一节说过：**编程就是用代码告诉计算机怎么完成一件事**。

那计算机是什么？

简单说，计算机就是一台**执行程序、处理数据的机器**。

它可以是：

- 你的笔记本电脑；
- 一台手机；
- 一台平板；
- 一台云服务器；
- 一个运行在机房里的后端服务机器；
- 甚至是一块智能手表、智能电视里的芯片设备。

它们形态不同，但底层做的事很像：

```text
输入 -> 处理 -> 存储 -> 输出
```

例如你在浏览器里打开一个网页：

```text
输入：你点击链接或输入网址
处理：浏览器请求网页文件、解析 HTML/CSS/JS、执行页面逻辑
存储：浏览器可能缓存文件，也可能保存登录状态
输出：屏幕上展示网页
```

再比如后端服务器处理登录请求：

```text
输入：前端发来的账号和密码
处理：后端程序校验账号密码
存储：读取数据库里的用户信息，可能写入登录记录
输出：返回登录成功或失败
```

所以，前端应用、后端服务、脚本、游戏、App，本质上都可以看作运行在计算机上的程序。区别只是它们运行的位置不同、处理的数据不同、输出的结果不同。

## 一、计算机不会思考，只会执行指令

人看到“登录”两个字，会理解背后的含义：输入账号密码、判断对错、进入系统。

但计算机不会理解“登录”这个抽象概念。它只能执行非常明确的指令：

```text
读取输入框里的账号
读取输入框里的密码
发送请求给服务器
等待服务器返回结果
如果结果是成功，就跳转页面
如果结果是失败，就展示错误提示
```

这就是为什么写程序时要把问题拆得很细。你不能只对计算机说“帮我做一个网站”，你必须告诉它每一步应该怎么做。

程序员写代码，本质上是在做两件事：

1. 把人的需求拆成明确步骤。
2. 用计算机能执行的方式表达这些步骤。

## 二、计算机处理信息的基本流程

计算机做任何事，都离不开四个动作：

| 动作 | 含义 | 例子 |
| --- | --- | --- |
| 输入 | 接收外部信息 | 键盘输入、鼠标点击、接口请求 |
| 处理 | 按规则计算和判断 | 计算价格、校验密码、执行 JS |
| 存储 | 保存数据 | 文件、图片、数据库、缓存 |
| 输出 | 给出结果 | 屏幕显示、声音、文件、网络响应 |

以前端页面为例：

```text
用户点击“加入购物车”
        ↓
浏览器收到点击事件
        ↓
JavaScript 修改购物车数据
        ↓
页面展示购物车数量 +1
```

这个过程仍然是：

```text
输入 -> 处理 -> 输出
```

如果中间还把购物车信息保存到本地缓存或后端数据库，就多了“存储”。

## 三、硬件和软件

计算机系统可以粗略分成两部分：

- **硬件**：摸得着的物理设备。
- **软件**：运行在硬件上的程序和数据。

例如：

| 类型 | 例子 |
| --- | --- |
| 硬件 | CPU、内存、硬盘、键盘、鼠标、屏幕 |
| 软件 | 操作系统、浏览器、微信、VS Code、Node.js、后端服务 |

硬件像身体，软件像指令和行为。

只有硬件，没有软件，计算机不知道要做什么；只有软件，没有硬件，程序也没有地方运行。

前端开发者每天接触的软件很多：

- 浏览器：运行网页和前端代码。
- VS Code：编写代码。
- Node.js：运行 JavaScript 工具和本地开发服务。
- 终端：输入命令，执行脚本。
- Git：管理代码版本。

这些软件本身也都是程序。

## 四、CPU：执行指令的核心

CPU（Central Processing Unit，中央处理器）通常被称为计算机的“大脑”。

它主要负责：

- 执行指令；
- 做数学计算；
- 做逻辑判断；
- 协调数据在不同部件之间流动。

例如你写了这样一段 JavaScript：

```js
const total = 99 * 3;
console.log(total);
```

从更底层看，计算机会做类似这样的事情：

```text
读取数字 99
读取数字 3
执行乘法
得到 297
把结果交给输出逻辑
```

真实过程比这个复杂得多，因为 JavaScript 不能直接被 CPU 理解，需要浏览器或 Node.js 这样的运行环境帮它转换和执行。但从学习角度看，可以先记住：

> **CPU 是真正执行计算和指令的核心部件。**

### CPU 的执行节奏

CPU 执行程序时，会不断重复类似这样的过程：

```text
取出一条指令 -> 理解这条指令 -> 执行这条指令 -> 继续下一条
```

这个过程会以极快的速度重复。我们感觉电脑能同时开浏览器、音乐、聊天工具，其实背后是操作系统在协调多个程序，让它们轮流或并行使用 CPU。

## 五、内存：程序运行时的临时工作区

内存通常指 RAM（Random Access Memory）。

它可以理解成计算机的“临时工作台”。

当你打开浏览器、VS Code 或一个网页时，相关程序和数据会被加载到内存里，CPU 才能快速使用它们。

例如你打开一个网页：

```text
网页文件从网络或缓存中读取
        ↓
浏览器把 HTML/CSS/JS 放到内存中处理
        ↓
JavaScript 创建变量、对象、函数
        ↓
页面运行起来
```

这也解释了几个常见现象：

- 打开的软件越多，占用内存越多。
- 页面里数据越大，占用内存越多。
- 刷新页面后，很多临时变量会重新创建。
- 电脑断电后，内存里的数据会丢失。

所以内存适合放“正在使用的数据”，不适合长期保存文件。

## 六、硬盘：长期保存文件的地方

硬盘、SSD 都属于长期存储设备。

它们可以理解成计算机的“仓库”。

你的代码文件、图片、视频、应用程序、操作系统，都保存在硬盘或 SSD 里。即使关机，这些数据也不会消失。

例如一个前端项目目录：

```text
my-project/
  index.html
  style.css
  main.js
  package.json
```

这些文件平时保存在硬盘里。当你用 VS Code 打开它们时，编辑器会把文件内容读到内存中；当你修改并保存时，修改后的内容又会写回硬盘。

可以这样理解：

```text
硬盘：长期保存
内存：临时使用
CPU：执行处理
```

一个生活类比：

```text
硬盘 = 书架，保存所有书
内存 = 书桌，放正在看的书
CPU = 正在读书和思考的人
```

书架很大，但拿取速度相对慢；书桌空间有限，但使用方便；真正完成阅读和思考的是人。

## 七、输入和输出设备

计算机需要和外部世界交互，所以需要输入设备和输出设备。

输入设备负责把外部信息交给计算机：

- 键盘；
- 鼠标；
- 触摸屏；
- 麦克风；
- 摄像头；
- 网络请求。

输出设备负责把计算机处理后的结果展示出来：

- 显示器；
- 音箱；
- 打印机；
- 文件；
- 网络响应。

对前端开发来说，最常见的输入输出是：

```text
输入：用户点击、输入、滚动、接口返回数据
输出：页面变化、弹窗、动画、请求结果
```

比如一个搜索框：

```text
用户输入关键词
        ↓
JavaScript 读取输入内容
        ↓
请求后端搜索接口
        ↓
浏览器展示搜索结果
```

这就是输入和输出在 Web 页面里的具体表现。

## 八、操作系统：管理硬件和软件的总管

操作系统也是一个程序，但它是非常特殊的程序。

常见操作系统包括：

- Windows；
- macOS；
- Linux；
- iOS；
- Android。

操作系统主要负责：

- 管理 CPU、内存、硬盘等硬件资源；
- 管理文件和文件夹；
- 启动和关闭应用程序；
- 分配每个程序能使用多少资源；
- 提供窗口、菜单、权限、网络等基础能力。

例如你打开浏览器时：

```text
你双击浏览器图标
        ↓
操作系统找到浏览器程序文件
        ↓
把浏览器加载到内存
        ↓
分配 CPU 时间给浏览器
        ↓
浏览器窗口显示出来
```

你平时写前端时，也一直在和操作系统打交道：

- 在文件夹里创建项目；
- 用编辑器打开代码文件；
- 在终端里执行 `npm install`；
- 用浏览器访问本地开发地址；
- 保存文件后触发页面刷新。

这些动作背后都有操作系统参与。

## 九、程序是怎么运行起来的

一个程序要运行，大致会经历这些步骤：

```text
程序文件保存在硬盘里
        ↓
用户或系统启动程序
        ↓
操作系统把程序加载到内存
        ↓
CPU 开始执行程序指令
        ↓
程序接收输入、处理数据、产生输出
```

例如打开浏览器：

```text
Chrome 程序文件保存在硬盘
        ↓
你点击 Chrome 图标
        ↓
操作系统把 Chrome 加载到内存
        ↓
CPU 执行 Chrome 的程序逻辑
        ↓
Chrome 显示窗口，等待你输入网址
```

例如运行一个前端开发服务：

```text
项目文件保存在硬盘
        ↓
你在终端输入 npm run dev
        ↓
Node.js 读取项目配置和依赖
        ↓
开发服务器程序启动
        ↓
浏览器访问 localhost 页面
```

所以当你以后看到“运行项目”“启动服务”“打开页面”，可以把它们都理解成：某个程序被加载到内存，并开始执行。

## 十、代码为什么不能直接被计算机理解

计算机最底层处理的是电信号。为了稳定表示电信号，计算机使用两种状态：

```text
0 和 1
```

也就是二进制。

所有数据最终都可以表示成 0 和 1：

- 数字可以表示成二进制；
- 文字可以通过编码表示成数字，再表示成二进制；
- 图片可以表示成一堆像素数据；
- 音频可以表示成一串采样数据；
- 程序指令也可以表示成二进制。

但人类直接写 0 和 1 太困难，所以我们使用更接近人类理解的编程语言：

```js
console.log("Hello");
```

计算机最终执行的不是这行文本本身，而是经过运行环境、解释器或编译器处理后的底层指令。

对前端来说：

- HTML 会被浏览器解析成页面结构；
- CSS 会被浏览器解析成样式规则；
- JavaScript 会被浏览器的 JavaScript 引擎解析、编译并执行；
- TypeScript 需要先转换成 JavaScript，再由浏览器或 Node.js 执行。

所以可以先建立一个简单认识：

> **我们写的是人能理解的代码，计算机最终执行的是机器能理解的指令。中间需要工具和运行环境做转换。**

## 十一、浏览器也是运行在计算机上的程序

前端开发最重要的运行环境是浏览器。

浏览器本身就是一个应用程序，运行在操作系统上。它会使用 CPU、内存、硬盘、网络和屏幕。

当你打开一个网页时，浏览器会做很多事：

```text
请求网页资源
读取 HTML
解析 CSS
执行 JavaScript
加载图片和字体
计算页面布局
把页面画到屏幕上
响应用户点击和输入
```

这说明前端代码不是“飘在网页里”的东西，它最终仍然运行在用户的计算机上。

所以前端开发者需要关心：

- 页面是否占用太多内存；
- JavaScript 是否执行太久导致页面卡顿；
- 图片和资源是否太大；
- 浏览器是否支持某个新特性；
- 用户的设备性能是否足够。

这些问题，本质上都和计算机如何运行程序有关。

## 十二、服务器也是计算机

服务器听起来很特殊，但本质上也是计算机。

只是它通常：

- 长时间开机；
- 放在机房或云平台；
- 主要通过网络接收请求；
- 不一定接显示器、键盘和鼠标；
- 运行后端服务、数据库、缓存等程序。

例如一个后端接口服务：

```text
服务器上运行着后端程序
        ↓
浏览器发送 HTTP 请求
        ↓
后端程序读取请求参数
        ↓
后端程序查询数据库
        ↓
服务器返回 JSON 数据
```

因此，前端和后端不是两个完全无关的世界。它们都是程序，只是：

| 类型 | 常见运行位置 | 主要职责 |
| --- | --- | --- |
| 前端程序 | 用户浏览器 | 展示页面、处理交互、请求接口 |
| 后端程序 | 服务器 | 处理业务逻辑、读写数据库、返回数据 |

理解这一点，对后面学习“前后端通信”“接口”“部署”很重要。

## 十三、为什么前端开发者要懂一点计算机

前端开发不需要一开始就深入学习 CPU 指令、操作系统内核、计算机组成原理。

但你至少要知道：

- 程序需要运行环境；
- 文件保存在硬盘里；
- 程序运行时会占用内存；
- CPU 负责执行计算和逻辑；
- 浏览器是运行前端代码的程序；
- Node.js 是运行 JavaScript 工具的程序；
- 服务器也是计算机，后端程序运行在服务器上；
- 页面卡顿、内存过高、文件过大，都和计算机资源有关。

这些知识会帮助你理解后面的内容：

- 为什么要保存文件；
- 为什么要启动本地开发服务；
- 为什么刷新页面后变量会重置；
- 为什么浏览器可以执行 JavaScript；
- 为什么前端需要请求后端接口；
- 为什么性能优化很重要。

## 十四、用一句话总结

计算机不是一个神秘黑盒。它本质上是一台执行程序的机器：

```text
接收输入 -> 执行程序 -> 处理数据 -> 保存数据 -> 输出结果
```

前端开发者写的 HTML、CSS、JavaScript，最终也要交给浏览器这个程序去解析和执行；浏览器又运行在计算机和操作系统之上。

所以，理解计算机的基本工作方式，是理解前端开发的第一层地基。
